# 默认节点切换与服务分流

默认节点切换会替换主代理的 `default` 出口，并同步已有的 `svc-default` 跟随出口。
它不要求重新编译全部服务分流；明确指定其他节点的服务继续使用其专属出口。

## 切换流程

1. 校验索引及节点连接参数，在临时文件中生成候选配置。
2. 使用已安装的真实 Xray `-test` 校验候选配置，通过后才替换主配置和已选节点信息。
3. 重启主代理并等待 TCP 监听；启用 UDP 时，同时等待 UDP 监听。
4. 重启、监听或文件写入失败时恢复原文件，并尝试恢复代理原先的运行状态。恢复不完整时报告失败。

操作与规则更新、服务分流共用部署锁。页面切换期间禁止重复点击，收到成功响应后重新加载实际状态；
请求失败时保留原按钮选择并显示错误，不提前显示“已切换”。部署新版页面后，已打开的旧页面需刷新一次。

## 旧分流节点标识

节点列表中的原始字段参与生成分流标识，地址格式等变化可能导致已有策略引用旧标识。
只有旧的已编译分流出口与当前列表中的唯一节点在地址、端口、UUID、传输、安全类型、SNI、路径和 WebSocket Host 上匹配，才恢复引用；
不会仅凭域名相同就改绑。能够恢复的策略在切换时同步修正出口标签和路由引用，分流页面读取和再次应用也支持恢复。

保存节点列表时会先检查已有服务策略。仍被分流引用且无法确认等价替代的节点不能直接修改或删除，
应先在服务分流中调整选择。确实无法恢复的旧策略不会被擅自改成其他节点；已有有效的编译出口也不会因默认切换被替换。

## 验收

切换后应同时确认已选节点、磁盘默认出口和代理服务正常，再从以该网关为默认路由的局域网设备新建连接，
通过 HTTPS 查询实际出口 IP。还应切回原节点再切入新节点，检查国内直连、国外代理、UDP/TCP DNS，
以及原本指定独立节点的服务策略。单看按钮颜色、磁盘配置或服务 active 不能代替真实出口验证。

该操作会重启代理，已有连接可能断开后重连。普通失败恢复不包含断电、SIGKILL 或存储故障下的完整系统恢复，
仍应保留配置备份或虚拟机快照。
